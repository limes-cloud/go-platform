# Schema-CRUD 通用管理页引擎 — 设计文档集

> 目标：让 admin-web 新增一个后台管理页，从「写 300~500 行 `.vue`」变成「写一份配置」；配置的无函数子集可由服务端下发，实现一套代码管理多个 App。

## 一页速览

| 项 | 结论 |
|---|---|
| 方案 | **自研配置编译器 + 复用现有 `art-*` 组件**。不引入 Formily / amis / form-create |
| 核心机制 | 四阶段编译流水线：`prefetch → resolve → project → descriptor`，一份模型配置产出 `{ form, search, columns, meta }` |
| 关键借鉴 | alien-form 的 `FieldDescriptor` 三场景投影、受限表达式引擎；Formily 的 `x-reactions` 联动协议形状 |
| 两层配置 | 第一层 TS 模块（函数可用，覆盖 49/49 页面）；第二层 JSON（TS 的无函数子集，服务端可下发，覆盖约 22~26 页面） |
| 渲染分界 | 表单/搜索/详情走「配置 → 表单运行时 → 字段组件」；**表格走「配置 → 直接渲染字段组件只读态」，不共享运行时** |
| 不做 | 任意页面布局、图表看板、多步向导、流程编排 —— 继续写 `.vue` |
