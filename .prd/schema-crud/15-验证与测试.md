## 2. 编译器单元测试（本期做）

**这是对上一轮决策的修正。** 之前定「本期不引入 vitest」，但读完 alien-form 后改变判断：

它的 `core/` 有 12 个测试文件 2408 行（测试量 ≈ 源码量，且重点压在安全边界、错误通道、越界 no-op、异步竞态这些容易在生产炸的地方，写得很认真）；而**我们最想抄的 `compiler/` 那 1169 行一行测试都没有**，`shared`/`cms`/`server` 全零测试。

编译器是纯函数（输入 `ModelSchema`，输出三份产物），**这是最容易也最该写测试的地方**。不写就等于放弃了唯一低成本的回归保护。

### 引入方式

```bash
pnpm add -D vitest @vue/test-utils
```

`vitest` 与项目现有的 vite 7 共用配置，成本很低。只测 `src/schema-crud/` 下的纯函数，**不测组件**（组件靠等价性验证）。

### 测试清单

| 文件 | 覆盖内容 |
|---|---|
| `compile/project.spec.ts` | **快照测试**：一份 model fixture → `{form, search, columns}` 三份产物快照。这是主力 |
| `compile/descriptors.spec.ts` | 每条描述符的 `match` 边界；匹配顺序（具体优先于通用）；primitive 兜底 |
| `compile/api.spec.ts` | RESTful 生成器的 4 种 naming（plural/snake/kebab/version）；`{ref}` 逃生口；未注册时报错而非抛异常 |
| `runtime/expression.spec.ts` | **安全用例最密**：13 个禁止标识符逐个测；`constructor`/`prototype`/`__proto__` 的静态访问、计算访问、对象键三种形式；函数调用/赋值/语句分隔/模板串一律拦截；白名单函数可用且不可传函数参数 |
| `runtime/reactions.spec.ts` | 13 个算子逐个测；嵌套路径 `a.b.c` 取值；`and`/`or` 逻辑；未知算子不生效且进错误通道 |
| `runtime/path.spec.ts` | 深路径读写；数字段造数组而非对象；`sortByOrder` 缺省排最后 |
| `validate.spec.ts` | 合法 schema 通过；缺必需字段报错；错误里带正确的 JSON path |
| `compile/errors.spec.ts` | 单字段错误只降级该字段；`api.list` 错误导致整页降级；错误对象的 `scope`/`path`/`key` 正确 |

### 快照测试的用法约定

快照是**变更检测**，不是正确性证明。约定：

- 改协议导致快照变化时，**必须逐行 review diff 再更新快照**，不许无脑 `-u`
- fixture 要覆盖真实场景：至少包含 `cron/task/group` 和 `manager/role` 两份真实配置

## 5. 反向验证：故意配错

配置驱动系统的健壮性要主动测，不能等生产暴露。**每一条都要有对应的自动化测试或人工检查项**：

| 错误配置 | 期望行为 |
|---|---|
| `type: 'nonexistent'` | 错误面板 + `console.warn`，该字段渲染占位输入框，**不静默变成 input** |
| `format: { type:'ref', name:'notRegistered' }` | 错误面板，该列渲染原始值 |
| `do: 'ref', name: 'notRegistered'` | 错误面板，该操作按钮不渲染（而不是点击后静默无反应） |
| `x-reactions` 里 `op: 'unknownOp'` | 该条不生效 + 错误面板，其余联动照常 |
| `rules: [{ type: 'host' }]`（async-validator 不认） | **编译期报错**，而不是校验静默失效 |
| `x-search: { operator:'between' }` 但缺 `paramMap` | 编译期报错 |
| `jsonFields: ['extra']` 但 `row.extra` 是非法 JSON | 置为 `{}` + 错误通道，弹窗仍能打开 |
| 整个 JSON 少一个大括号 | 错误面板 + monaco 定位到出错行，**不白屏** |
| `api.list` 指向不存在的 resource | 整页降级 + 错误面板 |

最后两条是「绝不白屏」原则的直接体现，见 [11](11-错误与可观测.md)。

## 6. 迁移期的双轨验证

P5 迁移每个页面时，**保留原 `.vue` 文件**（不删），这样：

1. 出问题时把菜单 `component` 指回原路径即刻恢复
2. 可以在预览页里并排对比新旧渲染结果
3. 原文件在该批次稳定运行一周后才删除

**原 `.vue` 文件在 P5 全部完成并稳定运行前一律不删。**
