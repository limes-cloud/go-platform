# 05 场景投影

三个场景：`form` / `search` / `table`。**详情不是第四个场景**，是 form 产物的渲染模式。

## 1. form 场景

### 结构规则

1. 顶层字段按 `order` 升序排（缺省 `Infinity` 排最后）
2. `groups[].keys` 里的字段被收进一个分组容器；**分组节点插在其首个成员的原始位置**
3. 未分组字段原地保留
4. `type==='object'` 的字段递归展开为嵌套点号 key（`setting.jwt.secret`）

### 分组是纯渲染层，不参与数据路径

alien-form 用 `x-layout` void 节点实现分组，代价是 `buildChildren` / `projectChildren` / `VoidFieldSlot` 三处都要写特殊分支，还要把 void 的值 `Object.assign` 摊回父级。**我们不这么做。**

投影产物直接给出分组结构，值始终按字段 key 平铺：

```ts
interface FormProjection {
  groups: Array<{
    title?: string          // 编译成 ArtForm 的 divider
    span?: number
    items: FormItem[]
  }>
  flat: FormItem[]          // 扁平化的全部项，供校验与提交使用
}
```

页壳渲染时两层 `v-for`。`ArtForm` 原生支持 `divider` 和 `span`（`manager/app/index.vue` 已在用这个方式做分组），所以不需要新组件。

### 三态：add / edit / detail

同一份 form 产物，靠 `provide/inject` 下发模式（移植 alien-form `field-mode.ts`，全文 16 行）：

```ts
export const FIELD_MODE = Symbol('fieldMode') as InjectionKey<Ref<FieldMode>>
// 页壳：provide(FIELD_MODE, mode)
// 字段组件：const mode = inject(FIELD_MODE, ref('edit'))
```

每个字段组件自己判断：

```vue
<template>
  <DisplayValue v-if="mode === 'detail'" :value="modelValue" :options="options" />
  <ElSelect v-else v-model="modelValue" v-bind="$attrs" />
</template>
```

编译期还要按模式做两件事（对应现有代码里 14 处 `disabled: dialogType==='edit'`）：

```ts
// 协议里写简写，编译期展开
disabledOn: 'edit'          // → props.disabled = (mode === 'edit')
```

## 2. search 场景

### 规则：form 的「减法 + 摊平」

**减法**（移植 alien-form `descriptors.ts:24-28`，5 行）：

```ts
function toSearchBase(f: ModelField, key: string): SearchFormItem {
  return {
    key,
    label: f.label,
    props: { placeholder: f.placeholder ?? `请输入${f.label}`, clearable: true },
    // 剥离：required / rules / defaultValue / x-reactions
  }
}
```

搜索场景**必须剥离校验和必填**——现有代码里有 9 处在搜索栏写了 `rules: [{required: true}]`，那是复制粘贴产生的错误配置。

**摊平**：`type==='object'` 和对象数组的子字段递归提到顶层，容器本身不进搜索栏。

### 准入：由存储事实决定

```ts
const visible = f['x-search']?.visible
             ?? f['x-database']?.filterable
             ?? f['x-database']?.index
             ?? false
if (!visible) continue
```

理由见 [03](03-模型协议.md) §3。

### 操作符与参数收集

每个搜索项编译时带上 `operator` 与可选 `paramMap`。页壳收集查询参数：

```ts
function collectSearchParams(items: SearchFormItem[], model: Record<string, any>) {
  const out: Record<string, any> = {}
  for (const it of items) {
    const v = model[it.key]
    if (v === undefined || v === '' || (Array.isArray(v) && !v.length)) continue
    if (it.operator === 'between' && it.paramMap) {
      const [a, b] = it.paramMap
      out[a] = v[0]; out[b] = v[1]
    } else {
      out[it.key] = v
    }
  }
  return out
}
```

**搜索条件的 owner 是页面，不是表单实例。** alien-form 为了「一切走同一个渲染器」把搜索值放在表单实例里，导致 schema 变化重建实例时要靠 `preserveValuesOnRebuild` + `initialValuesRef` 保住已填条件（`FilterForm.tsx:29-31`）。我们把搜索条件存在页面级 `reactive` 里，这个问题根本不存在。

### 展开/收起

`meta.searchCollapseAt`（默认 3）传给 `ArtSearchBar` 的 `defaultExpanded` / `showExpand`。**不要硬编码**（alien-form 硬编码成 4 且忽略了自己的配置字段，是个已存在的 bug）。

## 3. table 场景

### 规则：只取顶层，不下钻

```ts
function projectColumns(schema: ModelSchema, ctx: ProjectCtx): ColumnOption[] {
  const cols: ColumnOption[] = []
  if (ctx.schema.meta.showIndex !== false) cols.push({ type: 'index', width: '60', label: '#' })
  for (const [key, f] of sortByOrder(Object.entries(schema.fields))) {
    if (f['x-table']?.visible === false) continue
    if (!passFieldAuth(f, ctx)) continue                 // 字段级权限，见 10
    cols.push(matchDescriptor(f, key).toColumn(f, key, ctx))
  }
  if (ctx.schema.actions?.length) cols.push(operationColumn(ctx))
  return cols
}
```

与 form/search 的关键差异：**不递归下钻**。嵌套对象字段默认不出现在表格，除非标 `x-table.complex`（渲染摘要 + 详情按钮）。

### 操作列固定形态

现有 43 个页面的操作列**完全一致**，直接固化：

```ts
{ prop: 'operation', label: '操作', width: 120, fixed: 'right', useSlot: true, slotName: 'operation' }
```

## 4. FormatSpec — 替代 formatter 函数

依据：86 处 `formatter` = 时间 77 + 枚举查表 7 + 单位换算 1 + VNode 1。前三类可完全声明化。

```ts
type FormatSpec =
  | 'datetime' | 'date' | 'time' | 'filesize'
  | { type: 'enum'; source: OptionsSource; fallback?: string }
  | { type: 'mapping'; map: Record<string, string> }
  | { type: 'ref'; name: string }          // 逃生口 → registry.formatters（仅 TS 层 / @handler）
```

`{type:'enum'}` 替代那 7 处 `find()` 查表 formatter；`filesize` 替代 `resource/export` 的 `getFileSize(row.size * 1000)`；唯一的 VNode formatter（`manager/app/menu/index.vue:170` 的 `h(ElTag, ...)`）走 `{type:'ref'}`。

**注意**：如果按 [02](02-总体架构.md) §3 让表格单元格复用字段组件的 `detail` 模式，`{type:'enum'}` 大部分场景可以不用——Select 组件自己就会显示 label。`FormatSpec` 主要服务于「没有对应字段组件的纯展示列」。

## 5. SlotSpec — 替代 useSlot + slotName

依据：非 operation 插槽 = 开关 14 + 头像 10 + 图片 6 + 标签 6 + 纯文本 6 = 42/48。

```ts
type SlotSpec =
  | { type: 'statusSwitch'; api?: EndpointSpec; confirm?: string; auth?: string }
  | { type: 'avatar'; size?: number; fallbackField?: string }
  | { type: 'image'; width?: number; previewable?: boolean }
  | { type: 'tag'; source: OptionsSource; colorMap?: Record<string, string> }
  | { type: 'ref'; name: string }          // 逃生口 → registry.slots
```

### statusSwitch 要吸收现有的 5 处不一致

16 个页面有状态切换，基础形态统一（`ElMessageBox.confirm` → `PUT {id, status:!status}` → `refreshUpdate`），但有 5 处偏离：

| 页面 | 偏离 | 协议表达 |
|---|---|---|
| `ai-agent/prompt` | `status` 是数字 0/1 不是布尔 | `{ trueValue: 1, falseValue: 0 }` |
| `manager/dictionary/value` | 提交整行而非 `{id, status}` | `{ payload: 'row' }` |
| `cron/task` / `cron/worker` | 专用端点 `PUT /task/status` | `{ api: { method:'PUT', url:'/cron/api/v1/task/status' } }` |
| `manager/app` | 禁用时需 `ElMessageBox.prompt` 输入 ≥5 字原因 | 走 `{type:'ref'}` 逃生口（该页本就是本地 `.vue`） |

前三种能声明化，第四种明确走逃生口。这是「声明式覆盖大多数 + 逃生口兜住长尾」的典型例子。
