# 00 背景与目标

## 1. 问题

`web/admin-web` 现有 85 个 view / 21928 行。其中 **49 个页面使用 `useTable`，约 40 个是同一个模板的复制粘贴**，页面之间的差异只有五处：`apiFn`、`searchItems`、`columnsFactory`、`formItems`、`operationItems`。

### 重复度证据（全量扫描 `src/views/`）

| 指标 | 数值 |
|---|---|
| `useTable` 页面 | 49 |
| 其中渲染 `<ArtTable>` | 46 |
| `columnsFactory` / `ArtOperation` / `ArtSearchBar` / `ArtForm` 出现文件数 | 48 / 47 / 42 / 39 |
| `handleSearch` 逐字相同 | 40 / 45 |
| `handleSubmit` 逐字相同 | 38 / 40 |
| 列定义总数 | 316（均 6.6 列/页） |
| 行操作项总数 | 115（均 2.4 个/页） |
| 搜索项总数 | 95（均 2.3 个/页） |
| 表单项总数 | 182（均 4.7 个/页） |

### 配置的收敛度很高（意味着可以被声明式覆盖）

| 维度 | 分布 |
|---|---|
| `formatter` 用途 | 时间格式化 77 / 86 = **90%**；枚举查表 7；单位换算 1；VNode 1 |
| `rules` 形态 | `{required, message, trigger}` 三件套约 **99%**；`pattern` 12 处（其中 11 处是同一个 identifier 正则） |
| 非 operation 插槽 | 开关 14 + 头像 10 + 图片 6 + 标签 6 + 纯文本 6 = 42 / 48 |
| `popConfirm` | 47 个文件**各恰好 1 个**，全是删除 |
| componentMap 24 种类型 | 实际只用到 **13 种** |
| 搜索项类型 | 只用了 `input` 55 / `select` 37 / `treeselect` 3；**日期类 0 次** |
| 工具栏按钮 | 新增 41 + 跳转关联页 11 + 批量导出 1 |

结论：**80% 的配置面是窄的、规整的、可声明式表达的**。这是本方案成立的前提。

## 2. 目标

1. **新增标准 CRUD 管理页不写 `.vue`**：写一份配置（TS 或 JSON），页面自动出来
2. **配置的无函数子集可由服务端下发**：新增 App 需要管理界面时，在线配置即可，不必前端发版
3. **一套代码管理多个 App**：菜单已按 app 隔离下发（`menu.app` + `component` + `permission`），本引擎补齐「不必为新 App 写 views」这最后一环
4. **零侵入既有页面**：除 [13-既存缺陷修复](13-既存缺陷修复.md) 外，不改动现有 48 个页面的代码；迁移逐页进行、逐页可回滚

## 3. 非目标

明确不做，这类页面继续手写 `.vue`：

- 任意页面布局（卡片网格、三栏编辑器、主从左栏）
- 图表看板
- 多步向导、流程编排
- 表单设计器（`art-form-editor` 已存在且职责不同，本引擎**不依赖它**）
- 可视化配置器（本期不做，见 [14-实施计划](14-实施计划.md)）

## 4. 覆盖率预期

不要承诺 100%。按现有 49 个 `useTable` 页面实测分类：

| 分层 | 页面数 | 处理方式 |
|---|---|---|
| 配置完整覆盖（含声明式预设后） | 约 22~26 | JSON 或 TS 配置 |
| 只差 1~2 处函数缺口 | 约 10~13 | TS 配置（函数就地写） |
| 结构性无法覆盖 | 13 | 手写 `.vue`，菜单 `component` 指向原路径 |

结构性无法覆盖的 13 个文件及原因见 [01-技术选型](01-技术选型.md) 附录。

**混合模式是终态，不是过渡态。** 引擎必须假设永远有一部分页面走本地 `.vue`。

## 5. 成功标准

按优先级：

1. `src/views/cron/task/group.vue`（94 行，全字面量配置的黄金基线）能用配置完整复现，行为逐项一致
2. `src/views/manager/role/index.vue`（355 行，覆盖全部难点）能用 TS 配置完整复现
3. 新增一个标准 CRUD 页的配置量 ≤ 50 行，且 `pnpm build` 零类型错误
4. 配置写错时**渲染可归因的错误面板**，不白屏、不静默降级

验证方法见 [15-验证与测试](15-验证与测试.md)。
