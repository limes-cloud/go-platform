# 08 校验规则

## 1. 现状分布

156 处 `rules`，形态高度收敛：

| 形态 | 处数 | 说明 |
|---|---|---|
| `{required, message, trigger:['blur','change']}` | ~157 | **约 99%** |
| `pattern` 正则 | 12 | 其中 **11 处是同一个** `/^[a-zA-Z_][a-zA-Z0-9_]*$/`（标识符） |
| `type:'string'` | 12 | 与 pattern 配对 |
| `type:'url'` | 2 | |
| `min` | 1 | `manager/user` 账户最少 6 位 |
| 自定义 `validator` 函数 | 2 | `manager/user-form`、`cron/task`（cron 表达式） |
| `type:'email'` | 0 | |
| `type:'host'` | 1 | **async-validator 无此 type，校验静默失效**（见 [13](13-既存缺陷修复.md)） |

结论：**声明式规则能覆盖 99%**，自定义 validator 只需 2 个逃生口。

## 2. 不要重复 alien-form 的错误

alien-form 的 `ValidatorFormats` 类型定义了 email/url/phone/idcard/ip/zip 等 8 种格式，**但全仓库零实现、零消费方，是死类型**。它的 `x-validate` 只接受运行时值（函数/表达式/handler），想在 JSON 里表达「长度 2-20」都得写代码。

我们不能这样——Element Plus 底层的 `async-validator` 已经把 required / 长度 / 正则 / 数值范围 / 类型 全部免费提供了，直接映射即可。

## 3. RuleSpec 协议

```ts
type RuleSpec =
  | { required: true; message?: string }
  | { min?: number; max?: number; message?: string }        // 长度或数值范围（按字段 type 决定语义）
  | { pattern: PatternPreset | string; message?: string }
  | { type: 'url' | 'email' | 'integer' | 'number'; message?: string }
  | { unique: true; api?: EndpointSpec; message?: string }   // 异步唯一性
  | { validator: `@${string}` }                              // 逃生口 → registry.validators

type PatternPreset = 'identifier' | 'phone' | 'idcard' | 'ip' | 'zipcode' | 'chinese' | 'alphanum'
```

### 预设正则

`identifier` 覆盖那 11 处重复：

```ts
export const patterns: Record<PatternPreset, { re: RegExp; message: string }> = {
  identifier: { re: /^[a-zA-Z_][a-zA-Z0-9_]*$/, message: '只能包含字母、数字、下划线，且不能以数字开头' },
  phone:      { re: /^1[3-9]\d{9}$/,            message: '手机号格式错误' },
  idcard:     { re: /^\d{17}[\dXx]$/,           message: '身份证号格式错误' },
  ip:         { re: /^(\d{1,3}\.){3}\d{1,3}$/,  message: 'IP 地址格式错误' },
  zipcode:    { re: /^\d{6}$/,                  message: '邮政编码格式错误' },
  chinese:    { re: /^[一-龥]+$/,       message: '只能输入中文' },
  alphanum:   { re: /^[a-zA-Z0-9]+$/,           message: '只能输入字母和数字' },
}
```

注意 `src/router/utils/field.ts` 里已有一套 7 种正则（phone/email/idcard/url/chinese/number/alphanum）+ 3 档密码强度。**这两套必须合并成一处**，否则又是一个「唯一真相被复制两份」。倾向以 `schema-crud/presets/patterns.ts` 为准，`field.ts` 改为引用它。

### message 自动推导

`required` 不写 message 时按组件类型推导，消灭 157 处重复文案：

```ts
const verb = ['select','radiogroup','checkboxgroup','treeselect','date','upload'].includes(comp)
  ? '请选择' : '请输入'
message ??= `${verb}${field.label}`
```

## 4. 编译到 async-validator

`ArtForm` 的 rules 取自 `item.props.rules`（已核实模板 `:rules="item.props?.rules"`），所以编译目标明确：

```ts
function compileRules(f: ModelField, key: string, ctx: ProjectCtx): FormRule[] {
  const specs = [...(f.required ? [{ required: true as const }] : []), ...(f.rules ?? [])]
  return specs.map(s => {
    if ('required' in s) return { required: true, message: s.message ?? autoMessage(f), trigger: ['blur','change'] }
    if ('pattern'  in s) { const p = typeof s.pattern === 'string' && s.pattern in patterns
                             ? patterns[s.pattern as PatternPreset] : { re: new RegExp(s.pattern), message: '格式错误' }
                           return { pattern: p.re, message: s.message ?? p.message, trigger: 'blur' } }
    if ('unique'   in s) return { asyncValidator: makeUniqueValidator(f, key, s, ctx), trigger: 'blur' }
    if ('validator' in s) { const v = registry.validators[s.validator.slice(1)]
                            if (!v) { ctx.errors.push({ scope:'validator', path:key,
                                        message:`未注册的 validator: ${s.validator}` }); return null }
                            return { validator: v, trigger: 'blur' } }
    if ('type'     in s) return { type: s.type, message: s.message ?? `${f.label}格式错误`, trigger: 'blur' }
    return { ...s, trigger: 'blur' }        // min/max
  }).filter(Boolean) as FormRule[]
}
```

**`type:'host'` 这类 async-validator 不认的 type 要在编译期拦下并报错**，不能像现在这样静默失效。校验方式：对照 async-validator 支持的 type 白名单。

## 5. 异步唯一性校验

`x-database.unique` 驱动。这是后台高频需求（keyword 重名、账号重复），现有代码完全没做——只能等提交后由后端报错。

```ts
name: { label:'分组名称', type:'string', required: true,
        'x-database': { index: true, unique: true } }
```

编译期自动生成 asyncValidator：

- 请求 `GET {resource}s?{field}={value}&excludeId={currentId}`（编辑态排除自身）
- 防抖 300ms
- **网络失败时放行**（不阻塞用户提交，交后端兜底），但记录警告

若默认约定的接口形状不符，用 `{ unique: true, api: {...} }` 显式指定。

## 6. touched / dirty（两个参考项目都没有）

alien-form 的 14 个字段 signal 里没有 `touched`/`dirty`/`pristine`，导致 `validate()` 一次校验所有字段，**打开新增弹窗什么都没填就全表单飘红**——它只能靠「仅在 submit 时校验」规避（`SchemaForm.tsx:47`）。

我们必须做，因为它直接影响体验：

| 状态 | 用途 |
|---|---|
| `touched`（该字段失焦过） | **只校验 touched 字段**，避免打开即飘红 |
| `dirty`（值与初始值不同） | 「离开页面提示未保存」；提交时只发变更字段（可选） |
| `pristine`（整个表单未改动） | 提交按钮禁用 |

`ArtForm` 底层是 `ElForm`，`ElFormItem` 自带 blur 触发的逐字段校验，所以 `touched` 语义在 `trigger: 'blur'` 下基本自然成立。需要我们额外做的是：

- **提交时才做全量校验**（`formRef.validate()`）
- `dirty` 用 `JSON.stringify` 浅比较初始值与当前值（表单规模都很小，够用）
- 弹窗关闭前若 `dirty` 则二次确认

## 7. 搜索场景剥离校验

搜索场景**必须剥离 `required` / `rules` / `defaultValue`**。现有代码里有 9 处在搜索栏写了 `rules: [{required:true}]`，那是复制粘贴产生的错误配置——搜索条件不该有必填。

实现见 [05](05-场景投影.md) 的 `toSearchBase()`。

## 8. 校验错误的归属

校验失败有两类，必须区分：

| 类型 | 归属 | 呈现 |
|---|---|---|
| 用户输入不合规 | 字段级 | `ElFormItem` 的 error 文案（现有机制） |
| **配置本身写错**（未注册 validator、非法 type、正则语法错） | 编译期 | 进 `CompileError`，渲染错误面板，见 [11](11-错误与可观测.md) |

第二类绝不能表现为「校验静默不生效」——那正是 `type:'host'` 现在的样子。
