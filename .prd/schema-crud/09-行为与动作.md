# 09 行为与动作

## 1. 现状分布

115 个行操作项，`click` 回调行为可归为 10 类：

| 类 | 行为 | 处数 | 占比 |
|---|---|---|---|
| A | 打开本页弹窗（直接用 row） | 36 | 31% |
| B | 直接调删除接口 + `refreshRemove` | 47 | 41% |
| C | 先拉详情再打开弹窗（`GetXxx`） | 6 | 5% |
| D | `router.push` 跳转子页 | 8 | 7% |
| E | 打开抽屉/局部弹窗 + 附带拉数据 | 8 | 7% |
| F | 树形「新增子节点」（预填 parentId） | 3 | 3% |
| G | 确认 + 调非删除接口（立即执行/重置密钥/发布） | 3 | 3% |
| H | 下载/导出 | 2 | 2% |
| I | 打开局部子组件 `ref.show()` | 1 | 1% |
| J | 复制到剪贴板 | 1 | 1% |

`popConfirm` 47/115 = 41%，分布极规整：**每个有 operationItems 的文件恰好 1 个，全是删除**。

工具栏（全部在 `#left`，`#right` 零使用）：新增 41 + 跳转关联页 11 + 批量导出 1。

## 2. ActionItem 协议

A~D、F~H 八类可声明化，E/I/J 走逃生口：

```ts
type ActionItem = ActionBase & ActionBehavior

interface ActionBase {
  label: string
  icon?: string
  color?: 'primary' | 'warning' | 'danger' | 'success' | 'info'
  auth?: string                                  // 权限码
  confirm?: boolean | string                     // → popConfirm + popTitle
  hiddenWhen?: Condition | Condition[]           // 按行数据求值（现有代码缺失，见 §5）
  disabledWhen?: Condition | Condition[]
}

type ActionBehavior =
  | { do: 'edit' }                                                    // A：36 处
  | { do: 'edit'; prefetch: EndpointSpec }                            // C：6 处
  | { do: 'detail' }                                                  // 详情态（现无，新增能力）
  | { do: 'delete'; api?: EndpointSpec }                              // B：47 处
  | { do: 'addChild'; parentKey?: string }                            // F：3 处
  | { do: 'navigate'; to: string; query?: Record<string, string> }    // D：8 处
  | { do: 'request'; api: EndpointSpec; refresh?: RefreshMode; message?: string }  // G：3 处
  | { do: 'download'; url: string }                                   // H：2 处
  | { do: 'clipboard'; field: string; message?: string }               // J：1 处
  | { do: 'ref'; name: string }                                       // E/I：9 处逃生口

type RefreshMode = 'data' | 'create' | 'update' | 'remove' | 'none'
```

### 行字段引用

`navigate.query`、`download.url`、`request.api` 里用 `$row.` 前缀引用行字段：

```ts
{ do: 'navigate', to: 'Menu', query: { app: '$row.keyword' } }
```

覆盖 `manager/app/index.vue` 的 4 个跳转（`query: { app: keyword }`）。

**约定**：`$row.<path>` 支持嵌套路径；解析不到时进错误通道并阻止动作执行（不静默传 undefined）。

### `refresh` 语义对齐 useTable

`useTable` 返回 4 种语义化刷新，直接映射：

| `refresh` | 调用 | 语义 |
|---|---|---|
| `create` | `refreshCreate()` | 新增后回第一页 |
| `update` | `refreshUpdate()` | 更新后留在当前页 |
| `remove` | `refreshRemove()` | 删除后处理末页空数据 |
| `data` | `refreshData()` | 普通重取 |
| `none` | — | 不刷新（`cron/task` 的「立即执行」就是这样） |

`do:'delete'` 默认 `remove`，`do:'edit'` 提交后默认 `update`，`do:'request'` 必须显式指定。

## 3. ToolbarItem 协议

```ts
type ToolbarItem =
  | { type: 'create'; label?: string; auth?: string }                            // 41 处
  | { type: 'navigate'; label: string; to: string; query?: Record<string,string>; auth?: string }  // 11 处
  | { type: 'exportSelected'; label?: string; api: EndpointSpec; auth?: string }  // 1 处
  | { type: 'ref'; name: string }
```

`create` 的默认 label 是 `新增${meta.name}`，`navigate` 默认 `type="success"` + `Expand` 图标（对齐现有 11 处的形态）。

`exportSelected` 需要 `columns` 里有 `selection: true`，编译期校验这个约束。

## 4. openMode — 打开方式也是配置

借 alien-form `use-record-page.ts:36-45`：

```ts
meta: { openMode: { add: 'modal', edit: 'modal', detail: 'drawer' } }
```

| 值 | 行为 |
|---|---|
| `modal` | `ElDialog`，宽度取 `meta.dialogWidth`（默认 `480px`），`destroy-on-close` + `align-center` + `body-class="art-form-dialog"`（对齐现有 39 处形态） |
| `drawer` | `ElDrawer`，`size` 取 `meta.dialogWidth`（现有 2 处用 `480px`） |
| `page` | `router.push` 到独立路由 |

三种壳同一套 props，由页壳按 `openMode` 选择。

## 5. 按行数据动态显隐（现有代码缺失的能力）

现有 115 个操作项里 `hide` 和 `disabled` **零使用**。但有 1 处想做却写坏了：

`manager/user-form/index.vue:476` 写了 `show: (record) => !record.status`，而 `ArtOperation` 只认布尔 `hide`/`disabled`（不是函数），且没有 `show` 这个 prop —— **该配置完全无效，「发布」按钮对已发布的表单也会显示**。

这说明该能力是真实需求。协议里用 `hiddenWhen` / `disabledWhen` 表达，编译期把它们求值成 `ArtOperation` 认识的布尔 `hide` / `disabled`：

```ts
{ label:'发布', do:'request', api:{...}, hiddenWhen: { field:'status', op:'eq', value:true } }
```

**注意求值时机**：`ArtOperation` 的 `list` prop 是整个数组，不是按行的。所以页壳必须**为每一行计算一份 `OperationItem[]`**：

```ts
const rowActions = (row: any) => compiledActions
  .filter(a => !a.hiddenWhen || !evalConditions(a.hiddenWhen, row))
  .map(a => ({ ...a, disabled: a.disabledWhen ? evalConditions(a.disabledWhen, row) : false }))
```

`ArtOperation` 内部还会再按 `permission` 过滤一次（现有机制），两层过滤叠加。

## 6. 动作执行器与 CrudCtx

逃生口拿到的上下文：

```ts
interface CrudCtx {
  row: any
  schema: ModelSchema
  compiled: Compiled
  /** 表格数据与刷新 */
  data: Ref<any[]>
  refresh: { data(): void; create(): void; update(): void; remove(): void }
  /** 弹窗控制 */
  openDialog(mode: 'add' | 'edit' | 'detail', row?: any): void
  closeDialog(): void
  /** 页面能力 */
  router: Router
  message: typeof ElMessage
  confirm(text: string, title?: string): Promise<boolean>
  /** 页壳暴露的插槽 ref（用于 do:'ref' 打开局部子组件） */
  refs: Record<string, any>
}
```

注册：

```ts
// src/views/manager/role/role.crud.ts
registerCrud('manager.role', {
  actions: {
    menuTree: (row, ctx) => ctx.refs.menu?.show(row.id),      // 对应现有 menu.value?.show(record.id)
  },
})
```

`ctx.refs` 由页壳从 `#after` 插槽内的组件 ref 收集，这样 [02](02-总体架构.md) §6 的「方式 B」页面能把本地组件交给配置驱动的动作使用。

## 7. 提交流程

固化现有 38/40 个页面完全相同的 `handleSubmit`：

```
校验（formRef.validate）
  → jsonFields 序列化（对象 → JSON 字符串）
  → dialogType === 'add' ? api.create(values) : api.update(values)
  → ElMessage.success(add ? '创建成功' : '修改成功')
  → refreshCreate() / refreshUpdate()
  → 关闭弹窗
```

失败时：**不关闭弹窗、不清空已填内容**（现有代码依赖 axios 拦截器统一弹错，行为一致）。

## 8. 主从布局的支持方式

`manager/dictionary` / `manager/app/entity` / `resource/file` 三对页面是「左树/列表 + 右表格」。左栏结构性无法配置化（见 [01](01-技术选型.md) 附录），但**右栏可以**，前提是页壳支持：

```vue
<GenericCrudPage :config="config" :extra-params="{ dictionaryId: props.dictionaryId }" />
```

- `extraParams` 合并进 `useTable` 的 `apiParams`
- `extraParams` 变化时重置搜索条件并 `getData()`（对应现有 `watch(props.dictionaryId)` 的行为）
- `meta.immediate: false` 支持「父级未选中时不请求」（对应现有 5 处 `immediate: false`）
