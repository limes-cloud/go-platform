### D3/D4 的补充理由（读完 alien-form 后更强了）

用户选「只做 ArtForm」时我原本推荐保留 schema 逃生口。读完 alien-form 后确认用户的选择是对的：

- `FormRenderer` 的增量能力（嵌套容器 row/col/card/tabs、子表单重复段、计算字段）在 49 个 CRUD 页面里**零使用**
- 动态增删行 0 处、分步表单 0 处、唯一的分组表单（`manager/app`）靠 `divider` + `span`，`ArtForm` 原生支持
- alien-form 的 `x-format` 管道之所以存在，是因为它自伤的限制（叶子只能存 `string|number|boolean`，`form.ts:74-82` 直接 throw），导致多选值必须 JSON 字符串桥接。Vue 里数组就是数组，这层完全不需要

## 2. 本轮推翻的决策（需要你确认）

### R1：引入 vitest —— 推翻上一轮的「暂不引入」

上一轮你选了「暂不引入 vitest」，靠 `pnpm build` 类型检查 + 人工对照。**读完 alien-form 后我建议改为引入**，理由是新证据：

- alien-form 的 `core/` 有 12 个测试文件 2408 行（测试量 ≈ 源码量，重点压在安全边界、错误通道、异步竞态这些容易在生产炸的地方）
- 而**我们最想抄的 `compiler/` 那 1169 行一行测试都没有**，`shared`/`cms`/`server` 全零测试
- 本轮方案比上一轮重得多：多了受限表达式引擎（375 行，含安全禁止清单）、13 个算子的条件求值、四阶段流水线。这些是纯函数，**不测就等于放弃唯一低成本的回归保护**
- 表达式引擎的安全用例（禁止标识符、`__proto__` 三种访问形式、函数调用拦截）**必须有自动化测试**——这类漏洞靠人工对照发现不了

成本：`pnpm add -D vitest @vue/test-utils`，与项目现有 vite 7 共用配置。只测 `src/schema-crud/` 纯函数，不测组件。

**这条推翻了你的既有选择，需要你点头。若你仍倾向不引入，方案可以跑，但表达式引擎的安全边界就只能靠 code review 保证——我认为这个风险不该接受。**

### R2：协议范围扩大

上一轮的 `PageSchema` 是「columns + searchItems + formItems + actions」四份并列配置。本轮改为**一份字段声明投影出三个场景**（`fields` → form/search/table），因为 `FieldDescriptor` 机制能消灭「一个字段写三遍」。

代价：协议更抽象，配置作者要理解「投影」这个概念。收益：316 列 + 95 搜索项 + 182 表单项的重复面收敛成一份字段表。

## 4. 关键的可逆性设计

| 措施 | 作用 |
|---|---|
| 每页独立选择走配置或本地 `.vue`，由后端菜单 `component` 决定 | 迁移与回滚粒度到单页 |
| 引擎不修改现有 48 个页面代码（M0 除外） | 零侵入 |
| 原 `.vue` 文件在迁移全部完成并稳定前不删除 | 随时可回退 |
| JSON 是 TS 的严格子集，同一运行时 | 某页 JSON 表达不了时改成 `.crud.ts`，不用重写 |
| 先 TS 后 JSON、先本地后后端表 | TS 结构改起来编译器会报错；JSON 契约和数据库表一旦发布很难改 |
| `page_schema` 带 `version` + 草稿态 + 历史表 | 配置改错能回滚到上一版 |

## 5. 技术债与后续盘点约定

| 债 | 约定 |
|---|---|
| `registry` 里的自定义 handler / action / slot 会逐渐变多 | 每季度盘点一次，出现 3 个以上同形态的 `ref` 就提炼成新的声明式类型 |
| JSON Schema 与 `types.ts` 可能漂移 | **从 TS 类型生成，CI 校验同步**。这是 alien-form 踩过的坑（它的 `alien-form-schema.json` 已与代码不同步且是危险的不同步：两处 `additionalProperties: false` 却缺 `x-layout`/`x-effect`） |
| 组件元信息若被前后端共同依赖 | 抽成共享常量（proto 枚举或生成的 JSON）。alien-form 的 `MULTI_VALUE_COMPONENTS` 前后端各一份，是已存在的漂移点 |
| `field.ts` 与 `presets/patterns.ts` 两套正则 | M0 时合并成一处 |

## 6. 文档纪律

从 alien-form 学到的反面教训：**它的 README、`docs/`、CHANGELOG 三份文档全部落后于至少一次大重构**——README 宣传 6 种场景（含移动端卡片），代码里只有 3 种；`docs/scene-driven-architecture.zh-CN.md` 整篇 233 行描述的 API 全部不存在；CHANGELOG 提到的三个文件都不存在。结果是**读文档会被彻底误导，必须读源码**。

约定：

1. 本目录的文档随协议变更同步更新，协议改了但文档没改视为未完成
2. 每份文档里的**行数、处数、文件路径**都是可验证的事实，不写模糊的「大量」「很多」
3. 已核实与未核实的结论要区分标注（本目录已按此执行）
