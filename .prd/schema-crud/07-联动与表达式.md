# 07 联动与表达式

## 1. 现状需求规模

现有代码里 **53 处 `hidden`**，全部形如 `currentData.value.<field> !== 'X'`。分布：

| 页面 | hidden 处数 |
|---|---|
| `manager/app/menu` | 15（按菜单类型 M/A/BA/G 五分支） |
| `manager/app` | 10 |
| `ai-agent/prompt` | 7（按 `currentModel.type` 切 chat/image 两套字段） |
| `manager/oauther` | 6（按 `type` 切 base/email） |
| `manager/field` | 3 |
| 其余 | 12 |

另有 14 处 `disabled: dialogType==='edit'`（编辑时锁 keyword），完全同构。

## 2. 协议：借 Formily 的 `x-reactions` 形状

Formily 这块设计得最好，值得偷设计而不是装依赖：

```ts
interface Reaction {
  /** 依赖的字段路径。省略则由表达式自动推导（不推荐，见 §5） */
  dependencies?: string[]
  /** 条件。命中则应用 fulfill，否则应用 otherwise */
  when: Condition | Condition[]
  logic?: 'and' | 'or'            // 默认 'and'
  fulfill?: ReactionEffect
  otherwise?: ReactionEffect
}

interface ReactionEffect {
  visible?: boolean
  disabled?: boolean
  required?: boolean
  value?: any                     // 赋值
  props?: Record<string, any>     // 覆盖组件 props
  options?: OptionsSource         // 换选项
}

interface Condition {
  field: string                   // 支持嵌套路径 'setting.jwt.enable'
  op: 'eq'|'neq'|'in'|'notIn'|'empty'|'notEmpty'|'gt'|'gte'|'lt'|'lte'|'contains'|'between'|'pattern'
  value?: any
}
```

53 处 `hidden` 全部可写成：

```ts
'x-reactions': [{ when: { field: 'type', op: 'neq', value: 'M' }, fulfill: { visible: false } }]
```

`disabled: dialogType==='edit'` 用简写 `disabledOn: 'edit'`，编译期展开（见 [05](05-场景投影.md)）。

## 3. 求值：结构化条件，不是字符串表达式

**默认路径不用表达式引擎。** 13 个算子的结构化条件求值是一个纯函数：

```ts
export function evalCondition(c: Condition, values: Record<string, any>): boolean {
  const v = getDeepValue(values, c.field)      // 注意：支持嵌套路径
  switch (c.op) {
    case 'eq':       return v === c.value
    case 'neq':      return v !== c.value
    case 'in':       return Array.isArray(c.value) && c.value.includes(v)
    case 'notIn':    return Array.isArray(c.value) && !c.value.includes(v)
    case 'empty':    return v === '' || v == null || (Array.isArray(v) && !v.length)
    case 'notEmpty': return !(v === '' || v == null || (Array.isArray(v) && !v.length))
    case 'gt':       return Number(v) >  Number(c.value)
    case 'gte':      return Number(v) >= Number(c.value)
    case 'lt':       return Number(v) <  Number(c.value)
    case 'lte':      return Number(v) <= Number(c.value)
    case 'contains': return typeof v === 'string' && v.includes(String(c.value))
    case 'between':  return Array.isArray(c.value)
                       && Number(v) >= Number(c.value[0]) && Number(v) <= Number(c.value[1])
    case 'pattern':  try { return new RegExp(String(c.value)).test(String(v ?? '')) } catch { return false }
    default:         return true    // 未知算子：不生效 + 进错误通道
  }
}
```

结构与 alien-form `relation.ts:10` 的 `evaluateRelation` 一致，但**修掉它的一个限制**：它用 `formData[relation.field]` 平铺取值，不支持 `a.b.c`；我们有 25 处嵌套 key，所以必须走 `getDeepValue`。

**不复用 `art-form-editor/lib/relation.ts`**——那是表单设计器的运行时，跨目的耦合，设计器重构会连带炸这边。

## 4. 响应式：用 Vue 的 computed，不自建 signal 树

alien-form 给每条 reaction 包一个 `effect` 靠 signal 自动依赖收集（`form.ts:724-758`），需要 1150 行的字段树基建。Vue 里直接：

```ts
const fieldStates = computed(() => {
  const out: Record<string, FieldState> = {}
  for (const item of projection.flat) {
    out[item.key] = resolveReactions(item, formModel)   // formModel 是 reactive
  }
  return out
})
```

Vue 的依赖收集天然精确，不需要显式 `dependencies`。这也是不抄 signal 字段树的核心理由——**它在费力模拟 Vue 免费提供的东西**。

## 5. 逃生口：受限表达式 + `@handler`

结构化条件覆盖不了的情况（日期比较、字符串处理、跨字段算术），提供两条逃生口。

### 运行时值统一协议

借 alien-form `form.ts:791-832`：四种写法共享同一个求值入口，**不为联动/校验/格式化各造一套 DSL**。

```ts
type RuntimeValue =
  | string | number | boolean | null | any[] | object    // ① 字面量
  | `{{${string}}}`                                      // ② 受限表达式
  | `@${string}`                                         // ③ registry.handlers 查表
  | ((ctx: RuntimeCtx) => any)                           // ④ 直接函数（仅 TS 层）

function execRuntimeValue(rule: RuntimeValue, ctx: RuntimeCtx): any {
  if (typeof rule === 'function') return rule(ctx)
  if (typeof rule === 'string') {
    if (isExpression(rule)) return evalExpression(extract(rule), buildScope(ctx))
    if (rule.startsWith('@')) {
      const h = registry.handlers[rule.slice(1)]
      if (!h) { ctx.error({ scope:'handler', message:`未注册的 handler: ${rule}` }); return undefined }
      return h(ctx)
    }
  }
  return rule
}
```

**`@handlerName` 是让「必须写代码的逻辑」有明确出口、同时保持配置可 JSON 序列化的关键。** 这解决了「JSON 表达不了函数」与「服务端要下发配置」之间的矛盾。

### 受限表达式引擎

移植 alien-form `core/src/expression.ts`（375 行，零依赖纯 TS，可逐字复制）：手写 tokenizer + 递归下降 parser + AST 求值，**无 `eval`、无 `new Function`**。

支持：字面量（数字/字符串/布尔/null/数组/对象）、`+ - * / %`、`< <= > >=`、`=== !== == !=`、`&& || ??`（短路）、三元、一元 `! - +`、成员访问 `a.b` / `a["b"]`（null 短路）。

禁止：

```ts
const FORBIDDEN_IDS = new Set(['globalThis','window','document','process','Function','eval',
  'constructor','prototype','__proto__','new','function','class','import','this'])
const FORBIDDEN_KEYS = new Set(['constructor','prototype','__proto__'])
```

- **函数调用一律禁止**（遇到 `(` 直接报错）
- 赋值、模板字符串、`;` 语句分隔禁止
- 计算成员访问在**求值期**再查一次禁止 key（防 `a[k]` 里 k 运行时算出 `__proto__`）
- 标识符读取用 `hasOwnProperty.call(scope, name)`，不走原型链
- AST 按源码字符串缓存在模块级 Map，解析一次

**这是与 Formily 的关键差异**：Formily 的 `{{ }}` 是 `new Function('$root', 'with($root) { return (...) }')`（`packages/json-schema/src/compiler.ts:26`），在服务端下发配置的场景下等于 RCE。

安全定位要说清楚（照抄 alien-form CHANGELOG 的自陈）：**这是 defense-in-depth，不是 sandbox。** schema 来源仍应视为半可信，配置写入口要有权限管控。

### 建议：放开一个函数白名单

alien-form 禁止一切函数调用的代价是表达力天花板很低——没有 `includes`、没有日期比较、没有字符串处理，稍复杂的联动就得退回 `@handler`。

建议在 parser 里放开一个**纯函数白名单**（求值期按名字查表，不走 scope）：

```ts
const ALLOWED_FNS = {
  includes: (a, b) => Array.isArray(a) || typeof a === 'string' ? a.includes(b) : false,
  startsWith: (a, b) => String(a).startsWith(String(b)),
  length: (a) => a?.length ?? 0,
  lower: (a) => String(a).toLowerCase(),
  // 日期比较交给 handler，不进白名单（避免引入 dayjs 依赖到表达式层）
}
```

性价比明显高于「一律禁止」。**白名单必须是纯函数、无副作用、不接受函数参数。**

## 6. 性能陷阱：别让表达式隐式依赖全表单

alien-form 有一个协议层不可见的性能问题（`form.ts:843-865`）：`buildExpressionScope` 第一行就读 `runtime.values`，那是个 getter → 投影整棵字段树 → 读到每个叶子的 value signal。**结果是每条 `{{ }}` 都订阅了全表单所有字段，任一字段变化重算所有表达式**；而 `@handler` + `rt.get('a')` 是精确依赖。同一份语义、两种写法、性能差一个数量级。

我们的对策：**构建表达式 scope 时只注入 `dependencies` 声明的字段**（若未声明，则静态分析 AST 提取标识符——`expression.ts` 的 parser 已经有 AST，提取顶层 `Identifier` 是几行代码）。不要注入整个 values 对象。

## 7. 隐藏字段的值语义（必须显式约定）

alien-form 没定义这块，后果是：`display:"none"` 的字段从提交值里消失（`form.ts:529`），而后端只更新传入的列，叠加效果是**字段因联动被隐藏后数据库旧值被静默保留**。

我们的约定：

| 情形 | 行为 |
|---|---|
| 字段被 `visible: false` 隐藏 | **值保留在 model 里，正常提交** |
| 需要隐藏时清空 | 显式写 `fulfill: { visible: false, value: null }` |
| 隐藏字段的校验 | **跳过**（不校验不可见字段的 required） |

选「保留并提交」作默认，因为它行为可预测；要清空必须显式声明。这条要写进配置界面的提示文案。
