# 03 模型协议

## 1. 顶层：ModelSchema

```ts
interface ModelSchema {
  version: 1
  meta: ModelMeta
  api: ApiSpec
  fields: Record<string, ModelField>      // key 即字段路径段
  groups?: FieldGroup[]                   // 表单分组（纯渲染层，不影响数据路径）
  toolbar?: ToolbarItem[]
  actions?: ActionItem[]                  // 行操作
}

interface ModelMeta {
  name: string                            // 「角色」——弹窗标题与消息文案的词根
  rowKey?: string                         // 默认 'id'
  tree?: boolean                          // 树形表格：不分页 + excludeParams
  paginated?: boolean                     // 默认 true；tree=true 时强制 false
  openMode?: { add?: OpenMode; edit?: OpenMode; detail?: OpenMode }  // 'modal'|'drawer'|'page'
  dialogWidth?: string                    // 默认 '480px'
  searchCollapseAt?: number               // 搜索栏默认展开几项，默认 3
  jsonFields?: string[]                   // 声明为 JSON 字符串的字段，见 §5
  auth?: string                           // 页面级权限码
}
```

**`openMode` 让「打开方式也是配置」**（借 alien-form `use-record-page.ts:36-45`）：`modal`/`drawer` 走本页叠加层，`page` 走路由跳转。三种壳同一套 props。

`searchCollapseAt` 必须走配置——alien-form 的 `FilterForm.tsx:32` 把它硬编码成 4，而它的 `ModelMeta` 里明明有 `filterCount` 字段却没人读，这是个已存在的配置失效 bug。

## 2. 字段：ModelField

```ts
interface ModelField {
  label: string
  type: FieldValueType                    // 'string'|'number'|'boolean'|'object'|'array'
  component?: ComponentName               // 缺省由 type + x-database 推导
  props?: Record<string, any>             // 直通字段组件
  order?: number                          // 渲染排序，缺省 Infinity（排最后）
  tip?: string
  placeholder?: string
  defaultValue?: any
  fields?: Record<string, ModelField>     // type='object' 的子字段
  items?: ModelField                      // type='array' 的行结构

  dataSource?: OptionsSource              // 选项来源，见 06
  rules?: RuleSpec[]                      // 声明式校验，见 08
  required?: boolean                      // 简写，等价于 rules: [{ required: true }]

  'x-reactions'?: Reaction[]              // 联动，见 07
  'x-table'?: TableHint                   // 表格呈现
  'x-search'?: SearchHint                 // 搜索呈现
  'x-database'?: DatabaseFact              // 存储事实（只读信号）
  'x-auth'?: FieldAuth                    // 字段级权限，见 10
}
```

## 3. 三个 `x-` 扩展的职责分工

**这三者必须分开，不能混成一个 `display` 字段。** 混在一起会导致「想在表格隐藏但在表单显示」这类需求无法表达。

### `x-table` — 表格呈现（UI 偏好，可写）

```ts
interface TableHint {
  visible?: boolean                       // 默认 true
  width?: number | string
  minWidth?: number | string
  fixed?: 'left' | 'right'
  format?: FormatSpec                     // 见 05，替代 formatter 函数
  slot?: SlotSpec                         // 见 05，替代 useSlot+slotName
  complex?: boolean                       // 复杂列：渲染摘要 + 详情按钮
  order?: number
}
```

### `x-search` — 搜索呈现（UI 偏好，可写）

```ts
interface SearchHint {
  visible?: boolean                       // 默认跟随 x-database.filterable
  component?: ComponentName               // 搜索用的组件可与表单不同
  operator?: SearchOperator               // 见 §4，默认由 type 推导
  paramMap?: [string, string]             // operator='between' 时映射成两个请求参数
  span?: number
  order?: number
}
```

### `x-database` — 存储事实（能力约束，**前端只读不写**）

```ts
interface DatabaseFact {
  column?: string                         // 实际列名
  index?: boolean                         // 是否有索引
  filterable?: boolean                    // 缺省跟随 index
  sortable?: boolean                      // 缺省跟随 index
  unique?: boolean                        // 驱动唯一性异步校验，见 08
  nullable?: boolean
}
```

### 设计原则：能否筛 / 能否排由存储事实决定

借 alien-form `project.ts:122-125`，其原注释：

> 是否进入筛选区由后端存储事实决定：`filterable`（缺省跟随 `index`）。这是能力约束——字段能不能高效筛选取决于是否有索引，前端无权声明。

求值顺序：

```ts
const filterable = f['x-search']?.visible ?? f['x-database']?.filterable ?? f['x-database']?.index ?? false
const sortable   = f['x-database']?.sortable ?? f['x-database']?.index ?? false
```

注意 `sortable` **不看 `x-table.sortable`**——排序能力是存储事实，不接受 UI 层覆盖。

这条直接治后台系统的经典毛病：产品在配置里勾了「可排序」，那列没索引，生产上全表扫描。我们现有 68 处 `sortable: true` 全是纯前端排序（无 `@sort-change`），迁移时正好借这条重新审一遍——**前端排序只对当前页有效，在分页场景下是错的语义**。

## 4. 搜索操作符（两个参考项目都缺失的能力）

alien-form 的 filter 产物是平铺 `{field: value}`，操作符全靠后端约定（text 列自动 LIKE、数组自动 IN），**日期区间、金额 between 在协议里无法表达**。而这是后台刚需。

```ts
type SearchOperator = 'eq' | 'like' | 'in' | 'between' | 'gt' | 'gte' | 'lt' | 'lte'
```

默认推导：`string` → `like`，`number`/`boolean` → `eq`，有 `dataSource` → `in`（多选时）或 `eq`。

**`between` 的参数映射**：我们后端是 kratos + proto 校验的请求结构，不接受 `{field: [a, b]}` 形状，所以必须映射成两个参数：

```ts
{
  label: '创建时间',
  type: 'number',
  'x-search': {
    component: 'daterange',
    operator: 'between',
    paramMap: ['createdAtStart', 'createdAtEnd']   // → { createdAtStart, createdAtEnd }
  },
  'x-database': { index: true, filterable: true }
}
```

编译器产出 `SearchFormItem` 时把它编译成单个 `daterange` 控件，收集查询参数时按 `paramMap` 拆成两个键。**若后端未提供这两个参数，编译期报错**（在 `errors` 里，不静默）。

## 5. 嵌套字段与 JSON 字符串字段

### 嵌套 key

`ArtForm` 的 `getNestedValue` 已支持任意深度 `a.b.c`（已核实）。协议里通过 `fields` 嵌套声明，编译产出扁平的点号路径 key：

```ts
fields: {
  setting: { label:'配置', type:'object', fields: {
    jwt: { label:'JWT', type:'object', fields: {
      secret: { label:'密钥', type:'string' },      // → FormItem.key = 'setting.jwt.secret'
      expire: { label:'过期', type:'number' },
    }}
  }}
}
```

点号路径读写移植 alien-form `core/src/path.ts`（36 行纯函数）：`getDeepValue` / `setDeepValue`（按下一段是否为数字决定造 `[]` 还是 `{}`）/ `sortByOrder`。

### JSON 字符串字段（`extra` ⇄ `extraObject`）

现有代码有 5 个文件在做手工的 `JSON.parse` / `JSON.stringify` 转换（`manager/app`、`ai-agent/prompt`、`ai-agent/model`、`manager/oauther`、`recipe/ingredient`）。协议里用 `meta.jsonFields` 声明，页壳自动处理：

```ts
meta: { jsonFields: ['extra'] }
```

- 打开弹窗：`row.extra`（字符串）→ `form.extra`（对象）。**解析失败时置为 `{}` 并进错误通道，不抛异常**
- 提交前：`form.extra`（对象）→ `string`。空对象序列化为 `'{}'` 而非 `''`

**边界必须显式约定**（alien-form 完全没定义这块，是我们标为低确定性的原因，见 [16](16-决策记录.md)）：`null` → `{}`；空串 → `{}`；非法 JSON → `{}` + 错误通道；对象中的 `undefined` 值在序列化时被丢弃。

## 6. 组件注册表

借 alien-form `register/index.ts` 的形态：**一张表承载一个组件的全部元信息**。原则是「需要任一组件的配置时都必须走这张表，缺信息就在这里补，不要在别处另写一份」。

```ts
interface ComponentEntry {
  alias: string                    // 中文名（给配置界面下拉用）
  component: Component             // defineAsyncComponent(() => import('./Select.vue'))
  valueType: FieldValueType        // 数据类型
  kind: 'leaf' | 'complex' | 'layout'
  multiValue?: boolean             // 值是数组（驱动后端落 JSON 列 / junction 表的判断）
  searchComponent?: ComponentName  // 搜索场景的替代组件（如 select → select 多选）
  defaults?: Partial<ModelField>   // 选中该组件时带入的默认字段配置
  description?: string
}

export const components: Record<ComponentName, ComponentEntry> = { /* ... */ }
```

由这张表派生：字段组件映射、`buildComponentOptions()`（配置界面下拉）、`getDefaultField()`（新建字段模板）、投影时的 `valueType`/`multiValue` 判断。

**扩展自定义组件 = 在这张表加一项。**

⚠️ alien-form 有一个已存在的漂移点值得避免：`MULTI_VALUE_COMPONENTS` 在前端是注册表的 `multiValue: true`，在后端是 `field-plan.ts:6` 硬编码的 Set，同一份「唯一真相」被复制了两份。我们如果将来做后端建表联动，这份组件元信息应抽成前后端共享的常量（proto 枚举或生成的 JSON）。

## 7. 组件类型白名单

限定在现有 49 个页面实测用到的 13 种（componentMap 有 24 种，其余 11 种零使用）：

```ts
type ComponentName =
  | 'input' | 'textarea' | 'password'
  | 'number' | 'slider'
  | 'select' | 'radiogroup' | 'checkboxgroup' | 'treeselect'
  | 'switch'
  | 'date' | 'daterange' | 'datetime' | 'datetimerange'
  | 'upload' | 'icon' | 'code' | 'rich' | 'inputtag' | 'sqlbuilder'
```

编译到 `ArtForm` / `ArtSearchBar` 的 `componentMap` 时：

- `textarea` → `type:'input'` + `props.type:'textarea'`
- `password` → `type:'input'` + `props.type:'password'`（componentMap 里没有 `password`，见 [13](13-既存缺陷修复.md)）
- `date`/`daterange`/`datetime`/`datetimerange` → 必须由编译器补 `props.type`，因为四个键都映射到同一个 `ElDatePicker` 而组件本身不传 `type`（已核实，见 [13](13-既存缺陷修复.md)）
- **未命中白名单一律进错误通道 + `console.warn`，绝不静默 fallback 到 input**

## 8. 完整示例

```ts
// src/views/cron/task/group.crud.ts
export default defineCrudPage({
  version: 1,
  meta: { name: '任务分组', auth: 'cron:task:group:query' },
  api: { service: 'cron', resource: 'task_group', version: 'v1', naming: 'snake' },
  fields: {
    name:        { label: '分组名称', type: 'string', required: true,
                   'x-database': { index: true, filterable: true, unique: true } },
    description: { label: '分组描述', type: 'string', component: 'textarea', required: true,
                   'x-search': { visible: false } },
    createdAt:   { label: '创建时间', type: 'number',
                   'x-table': { format: 'datetime' },
                   'x-database': { index: true, sortable: true } },
  },
  toolbar: [{ type: 'create', auth: 'cron:task:group:add' }],
  actions: [
    { label: '修改分组', do: 'edit',   color: 'warning', auth: 'cron:task:group:update' },
    { label: '删除分组', do: 'delete', color: 'danger', confirm: true, auth: 'cron:task:group:delete' },
  ],
})
```

对照：现有 `src/views/cron/task/group.vue` 是 94 行。上面这份 28 行，且**一份字段声明同时产出表格列、搜索项、表单项**——`name` 字段不需要写三遍。
