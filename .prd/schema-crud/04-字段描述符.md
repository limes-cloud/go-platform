# 04 字段描述符

## 1. 要解决的问题

现有代码里，一个字段要在三个地方各写一遍：

```ts
// searchItems
{ label: '角色状态', key: 'status', type: 'select', props: { options: [...] } }
// columnsFactory
{ prop: 'status', label: '角色状态', useSlot: true, slotName: 'status' }
// 加上模板里的
<template #status="{ row }"><el-switch :before-change="handleUpdateStatus(row)" /></template>
```

加一种新字段类型（比如「地区级联」）要改三处、漏一处就出 bug。统计上这个重复面是 316 列 + 95 搜索项 + 182 表单项。

## 2. 机制

移植 alien-form `packages/shared/src/compiler/types.ts:188-197`。作者原注释：「新增字段类型 = 加一条描述符，form / filter / table 自动跟上」。

```ts
interface FieldDescriptor {
  name: string
  /** 命中条件。有序数组，第一个命中生效 */
  match: (field: ModelField, key: string) => boolean
  /** form 场景（新增/编辑/详情共用一份产物） */
  toForm: (field: ModelField, key: string, ctx: ProjectCtx) => FormItem
  /** search 场景。返回 undefined = 该字段不进搜索栏 */
  toSearch: (field: ModelField, key: string, ctx: ProjectCtx) => SearchFormItem | undefined
  /** table 场景 */
  toColumn: (field: ModelField, key: string, ctx: ProjectCtx) => ColumnOption
}
```

`ProjectCtx` 提供编译期上下文：

```ts
interface ProjectCtx {
  scene: 'form' | 'search' | 'table'
  schema: ModelSchema          // 整份模型（用于跨字段判断）
  store: Record<string, any>   // prefetch 阶段的字典缓存
  errors: CompileError[]        // 收集错误，不抛异常
  components: typeof registry.components
}
```

## 3. 匹配顺序与兜底

**有序数组，第一个 `match` 命中生效，末尾 primitive 兜底。** 顺序即优先级，具体在前、通用在后。

```ts
export const descriptors: FieldDescriptor[] = [
  statusDescriptor,        // status 布尔字段 → 表格渲染开关
  enumDescriptor,          // 有 dataSource → 表格用 label 翻译，搜索用 select
  mediaDescriptor,         // upload/图片/头像 → 表格渲染图片
  datetimeDescriptor,      // 时间字段 → 表格格式化，搜索用 daterange + between
  objectDescriptor,        // type='object' → 表单嵌套，搜索摊平，表格默认不展示
  arrayDescriptor,         // type='array'
  primitiveDescriptor,     // 兜底：input
]
```

## 4. 内置描述符

依据现有 49 个页面的实测分布（见 [00](00-背景与目标.md)），六条描述符覆盖 42/48 非 operation 插槽 + 84/86 formatter：

| 描述符 | match | toForm | toSearch | toColumn |
|---|---|---|---|---|
| `status` | `type==='boolean'` 且 key 为 `status`/`enable` | `switch` | `select`（启用/禁用） | `slot: statusSwitch`（带确认 + `PUT {id, status:!status}`） |
| `enum` | 有 `dataSource` | `select`/`radiogroup`/`treeselect` | `select`（`operator:'in'`，>50 项转远程搜索） | 用 `dataSource` 把值翻译成 label（`format: enum`） |
| `media` | `component` 是 `upload` 或 `x-table.slot` 是 `avatar`/`image` | `upload` | **`undefined`**（不进搜索） | `slot: avatar` / `slot: image` |
| `datetime` | `x-table.format` 是 `datetime`/`date`，或 key 以 `At`/`Time` 结尾 | `datetime`（多数场景只读，见注） | `daterange` + `operator:'between'` + `paramMap` | `format: 'datetime'` |
| `object` | `type==='object'` 有 `fields` | 递归产出嵌套 key 的 FormItem | **子字段摊平到顶层**（见 [05](05-场景投影.md)） | 默认 `visible:false`，除非 `x-table.complex` |
| `primitive` | 兜底 | `input` | `input` + `operator:'like'` | 纯文本 |

注：`createdAt`/`updatedAt` 这类审计字段通常只在表格出现，不进表单。约定：**`x-database.nullable === false` 且无 `defaultValue` 的字段若从未在 `groups` 中出现，则不进 form 场景**——或者更简单，显式写 `'x-form': { visible: false }`。倾向后者，显式优于推导。

## 5. 新增一种字段类型的完整步骤

以「地区级联选择」为例：

1. `registry.components` 加一项 `cascader`（含 `alias`、`component`、`valueType`、`defaults`）
2. `descriptors` 数组里加一条：

```ts
const regionDescriptor: FieldDescriptor = {
  name: 'region',
  match: (f) => f.component === 'cascader',
  toForm:   (f, key) => ({ key, label: f.label, type: 'cascader',
                           props: { ...f.props, options: resolveOptions(f, ctx) } }),
  toSearch: (f, key) => ({ ...toSearchBase(f, key), type: 'cascader',
                           props: { ...f.props, props: { checkStrictly: true } } }),
  toColumn: (f, key) => ({ prop: key, label: f.label,
                           formatter: (row) => joinRegionNames(row[key], ctx.store) }),
}
```

3. 完成。表格列、搜索项、表单项自动跟上。

**不需要改页壳、不需要改编译器主流程、不需要在三个地方各改一遍。**

## 6. 与「插槽预设」的关系

`toColumn` 返回的 `slot: SlotSpec` 不是最终的插槽实现，而是一个**声明**。页壳按 `SlotSpec.type` 从 `presets/slots.ts` 取对应组件渲染。四种预设及其覆盖依据见 [05](05-场景投影.md)。

分工：**描述符决定「这类字段在表格里用哪种呈现」，预设决定「那种呈现具体长什么样」。** 两者解耦，所以换 UI 不用改描述符。

## 7. 测试要求

描述符是纯函数（输入 `ModelField`，输出三份配置），**这是最该写快照测试的地方**。

alien-form 的教训：它的 `compiler/` 那 1169 行**一行测试都没有**，而 `core/` 有 2408 行测试。我们要反过来——编译层必须有测试，见 [15](15-验证与测试.md)。
