# 13 既存缺陷修复

动工前先修。理由：**这些缺陷不修，引擎会继承它们；而 JSON 驱动下静默失败比报错危险得多。**

## 1. 组件类型名映射不一致（已核实，生产中）

`src/router/utils/field.ts` 的 `toFormItems()` 产出驼峰类型名，`src/components/core/forms/art-form/index.vue:128` 的 `componentMap` 键是全小写，`getComponent()` 第 316 行是：

```ts
return componentMap[type as keyof typeof componentMap] || componentMap['input']
```

**静默降级。** 实测对照（我逐个 grep 比对过两边）：

| `field.ts` 产出 | `componentMap` 实际键 | 结果 |
|---|---|---|
| `inputNumber` | `number` | ❌ 降级为 ElInput |
| `radioGroup` | `radiogroup` | ❌ |
| `checkboxGroup` | `checkboxgroup` | ❌ |
| `timePicker` | `timepicker` | ❌ |
| `datePicker` | `date` | ❌ |
| `password` | **不存在** | ❌ |
| `input` / `select` / `upload` | 同名 | ✅ |

**9 种里 6 种失效。** 消费方 `src/views/manager/user/index.vue:558` 正在生产使用：

```ts
ListField({ page:1, pageSize:50, status:true }).then(res => {
  formItems.value = formItems.value.concat(toFormItems(res.list))
})
```

即后端在 `field` 表里配的数字/单选/多选/日期/时间/密码字段，**现在全部渲染成普通文本框**。

### 修法

1. `componentMap` 查找前做 key 归一化：小写 + 去 `-`/`_`
2. 补别名：`password` → `input` + `props.type='password'`；`textarea` → `input` + `props.type='textarea'`
3. **未命中时 `console.warn` 并在 dev 环境显式提示，不再静默 fallback**
4. `art-search-bar/index.vue` 同样处理（它有一份独立的 `componentMap`）

顺带把 `field.ts` 的正则集合（7 种 + 3 档密码强度）与新的 `schema-crud/presets/patterns.ts` 合并成一处，见 [08](08-校验规则.md) §3。

## 2. 日期变体形同虚设（新发现，已核实）

`art-form/index.vue:137-140` 和 `art-search-bar/index.vue:134-136`：

```ts
date:          ElDatePicker,  // 日期选择器
daterange:     ElDatePicker,  // 日期范围选择器
datetime:      ElDatePicker,  // 日期时间选择器
datetimerange: ElDatePicker,  // 日期时间范围选择器
```

四个键都映射到同一个 `ElDatePicker`，但**代码里没有任何地方把 `type` 传给它**——我 grep 过两个文件，没有 `type: item.type` 之类的推导，也没有 `dateTypeMap`。

后果：写 `type: 'daterange'` 得不到范围选择器，必须自己在 `props.type` 里再写一遍。

这也解释了为什么现有 95 个搜索项里**日期类 type 一次都没用过**——大概试过不好用就绕开了。而 [03](03-模型协议.md) 的搜索操作符 `between` 依赖 `daterange` 可用。

### 修法

`getProps()` 时按 schema type 推导补 `props.type`：

```ts
const dateTypeMap = { date:'date', daterange:'daterange', datetime:'datetime',
                      datetimerange:'datetimerange', month:'month', year:'year', week:'week' }
if (item.type in dateTypeMap && !props.type) props.type = dateTypeMap[item.type]
```

## 3. 迁移会自动消灭的死配置（不单独修）

这些是「配了但组件不认」，迁移到配置驱动后由 TS 类型检查拦住，不需要单独修：

| 问题 | 处数 | 位置 |
|---|---|---|
| `:show-button="false"`（`ArtForm` 只有 `showCancel`/`showSubmit`） | **27** | 各 CRUD 页模板 |
| `suffix`（`ArtForm` 无此渲染逻辑） | 5 | `recipe/ingredient/classify.vue:133`、`recipe/ingredient/index.vue:279,313`、`recipe/recipe/classify.vue:142`、`recipe/recipe/index.vue:280` |
| `suffixTip` | 2 | `ai-agent/model/index.vue:284,316` |
| `show: (record)=>...`（`ArtOperation` 只认布尔 `hide`） | 1 | `manager/user-form/index.vue:476` — 「发布」按钮对已发布表单也显示 |
| `type:'input-number'`（应为 `number`） | 1 | `configure/template/index.vue:194` |
| `type:'host'` rule（async-validator 无此 type，**校验静默失效**） | 1 | `manager/oauther/index.vue:304` |
| `formItems` 写成二维数组（渲染出 2 个空表单项） | 1 | `recipe/recipe/index.vue:235` |
| `cellClassName:'test'` 调试残留 | 1 | `resource/file/file.vue:387` |
| `parseTime` 与 `formatTime` 混用 | 2 | `manager/feedback/classify/index.vue:184,190` |
| 伪 `computed`（无任何响应式依赖） | 7 | `configure/business`、`configure/template`、`manager/dept/classify`、`manager/dictionary/value`、`manager/feedback/classify`、`manager/feedback/index`、`manager/notice/classify` |

**`recipe/*` 那 5 处 `suffix` 和 `ai-agent/model` 的 2 处 `suffixTip` 反映了一个真实未满足的需求**：输入框后缀按钮（「AI 生成图片/文案」）。协议里应该支持：

```ts
{ ..., suffix?: { type: 'button'; label: string; action: `@${string}` } }
```

编译时利用 `ArtForm` 已有的 `#[item.key]` 具名插槽实现，无需改 `ArtForm`。

## 5. 一个不修但要记录的设计问题

`useTable` 里这些配置**全链路是死代码**，迁移时不要在协议里为它们留位置：

| 配置 | 使用处数 |
|---|---|
| `performance.enableCache` / `cacheTime` / `debounceTime` / `maxCacheSize` | **0**（`TableCache`、4 种失效策略、定时清理、`cacheInfo` 全部未被调用） |
| `transform.dataTransformer` / `responseAdapter` | **0** |
| `core.paginationKey` | **0**（全靠全局 `tableConfig`） |
| `hooks.onError` / `onCacheHit` / `onLoading` | **0** |
| `debug.enableLog` | **0** |
| `MAX_RETRIES`（`src/utils/http/index.ts`） | 设为 **0**，等于重试逻辑关闭 |

实际用到的只有：`apiFn`(49)、`apiParams`(49)、`columnsFactory`(48)、`excludeParams`(6)、`immediate:false`(5)、`hooks.onSuccess`(3)、`hooks.resetFormCallback`(1)。

**协议只覆盖这 7 项。** 是否清理 `useTable` 里的死代码不在本期范围（属于独立的技术债清理）。
