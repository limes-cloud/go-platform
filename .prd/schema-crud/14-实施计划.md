## 2. 阶段划分

| 阶段 | 内容 | 产出 | 回滚方式 |
|---|---|---|---|
| **P0** | M0 | 两个静默失败的缺陷修掉 | 独立 commit，直接 revert |
| **P1** | M1 → M2 → M3 → M4 | 编译器可跑，有单测（见 §4） | 未接线到任何生产菜单，无影响 |
| **P2** | M5 + M6 | 通用页壳 + 预览页 + 两份本地 schema | 同上 |
| **P3** | **等价性验证**（门槛，见 [15](15-验证与测试.md)） | 两个目标页面逐项对照通过 | 不通过则回 P1 调整协议 |
| **P4** | M7 后端表 + 管理页 | schema 可在线编辑、发布、回滚 | 表新增，不影响既有接口 |
| **P5** | M8 逐页迁移 | 约 35 页 | 每页把菜单 `component` 指回原 `.vue` |

**P3 是硬门槛。** 协议设计错了要在这里发现，而不是迁移了 20 个页面之后。

## 3. 迁移顺序（P5）

按复杂度递增，每批做完观察一周：

| 批次 | 页面 | 数量 | 特征 |
|---|---|---|---|
| 第 1 批 | `cron/task/group`、`cron/worker/group`、`cron/worker/index`、`cron/task` 相关 | 4 | 最简，全字面量配置，无 computed |
| 第 2 批 | `manager/form-scene`、`manager/app/form`、`ai-agent/prompt/classify`、`ai-agent/secret/group`、各类 `classify` 管理页 | ~12 | 标准 CRUD，无树无嵌套 |
| 第 3 批 | 带 status 开关 + 图片/头像插槽的页面 | ~10 | 验证插槽预设 |
| 第 4 批 | 树形页面（`manager/dept`、`manager/role`、`recipe/recipe/classify`）+ 主从右栏 | ~6 | 验证 `{from:'self'}` 与 `extraParams` |
| 第 5 批 | 带 `jsonFields` 的（`ai-agent/model`、`recipe/ingredient`） | 2 | 验证 JSON 字符串双向映射 |
| 不迁移 | [01](01-技术选型.md) 附录的 13 个 + 主从三个左栏 | 16 | 保持本地 `.vue` |

**第 4、5 批对应两个低确定性决策**（见 [16](16-决策记录.md)），若失败则这两批留本地 `.vue`，不影响前三批成果。

## 5. 工作量粗估

只作为排期参考，不作承诺：

| 阶段 | 规模 |
|---|---|
| P0 | 半天 |
| P1 | 编译器约 800~1000 行（其中 ~410 行是移植 alien-form 的流水线、375 行是移植表达式引擎、36 行是 path） |
| P2 | 页壳约 300~400 行 + 字段组件 detail 模式改造（每个组件加 3~5 行） |
| P3 | 1~2 天对照 + 修问题 |
| P4 | 后端一个标准 kratos 模块（entity/repo/service/app/proto）+ 一个管理页 |
| P5 | 平均每页 30~60 分钟（写配置 + 对照验证） |

移植部分占 P1 的一半以上，且都是纯函数——这是选择「抄架构而非自己想」的直接收益。

## 6. 不进本期的事

| 项 | 理由 |
|---|---|
| 可视化配置器 | 成本远高于收益；draft⇄schema 双向映射是长期 bug 源（alien-form 的 `authoring.ts` 已经在靠猜字段类型）。先用 monaco + JSON Schema 补全 |
| 百分比灰度 | 白名单预览已覆盖主要场景，见 [12](12-Schema治理.md) §5。表设计留字段位置 |
| 从数据库表结构自动生成 schema 草稿 | 后端已有 `LoadEntity` 反射能力（`api/manager/entity`），但生成逻辑要单独设计。**这是 P5 之后最高价值的增量**，不在本期 |
| 清理 `useTable` 死代码 | 独立技术债，与本引擎无耦合 |
| 打通 `Parser` 的多 app 分组 | `parser.ts` 已有 `GetApps()` / `menus: Map<appKeyword, routes>` / `homes`，但 `beforeEach.ts:processBackendMenu` 只调了 `GetRouter()` 和 `GetPermission()`。这是「一套代码多 App」的另一半，独立任务 |
| `X-App-Key` 运行时可切换 | 现在是 `VITE_APP_KEY \|\| 'manager'` 编译期定值，`store/modules/app.ts` 的 `keyword` 硬编码 `'manager'`。真要多 App 必须改，但独立于本引擎 |

最后两项要提醒：**它们不做，「一套代码管多个 App」就只完成了一半**——引擎解决了「不用为新 App 写 views」，但运行时切换 App 的能力仍然缺失。建议 P4 之后单独立项。
