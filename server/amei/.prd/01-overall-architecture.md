# 总体架构

> 状态：方案设计
> 日期：2026-11-12
> 范围：`amei`、`amei-media`、`amei-adapters` 的职责、数据流和部署边界

## 1. 目标

amei 要解决四件事：

1. 手机号用户直接注册/登录，不需要预先维护一套固定账号。
2. 一个手机号用户可以绑定和管理多个平台开放平台账号。
3. 一次提交文章、图文或视频，批量分发到多个平台；每个平台独立成功或失败。
4. 从平台官方接口拉取内容数据，统一展示曝光、播放、阅读、互动和涨粉。

平台发布必须走官方开放平台。对于没有公开内容发布 API 的平台，系统显示“能力未开通”，
并保持发布按钮禁用；不切换到创作者网页后台、Cookie 登录或逆向接口。

## 2. 三层架构

```text
┌─────────────────────────────────────────────────────────────┐
│ amei 控制面                                                 │
│ 手机号用户 / 内容版本 / 平台账号索引 / 批次 / 调度 / 看板   │
└───────────────┬─────────────────────────────┬───────────────┘
                │                             │
                ▼                             ▼
┌───────────────────────────────┐   ┌───────────────────────────────┐
│ amei-media 媒体层             │   │ amei-adapters 平台适配层      │
│ 上传 / 校验 / 转码 / 封面     │   │ OAuth / 平台素材 / 发布 / 取数 │
│ 字幕 / 对象存储 / 签名 URL    │   │ 每个平台独立插件与凭据存储    │
└───────────────────────────────┘   └───────────────────────────────┘
```

### 2.1 `amei` 控制面

- 手机号注册/登录、短信 OTP、JWT 或安全会话；
- 用户与平台账号的归属关系；
- 内容条目、不可变内容版本、素材引用；
- 发布批次、单平台任务、定时、重试、取消和审计；
- 适配器注册、能力发现、健康检查；
- 指标标准化、聚合、看板和人工补录。

控制面不保存平台密码、cookie、OAuth access/refresh token、二维码 ticket 或浏览器 profile。

### 2.2 `amei-media` 媒体层

独立仓库、独立服务、独立对象存储命名空间，避免控制面和平台适配器重复处理大文件。

- 客户端直传对象存储，服务端签发短期上传票据；
- 文件类型、大小、时长、分辨率、码率、音轨、封面和字幕校验；
- 视频转码为平台可接收的母版和派生版本；
- 图片压缩、封面裁切、EXIF 清理；
- 素材状态机、哈希去重、版权声明和授权附件；
- 向控制面和适配器签发短 TTL 下载 URL。

`amei-media` 不理解抖音/B 站等平台字段，只提供可信媒体资产。

### 2.3 `amei-adapters` 平台适配层

- 平台 OAuth/授权发起、回调换取 token、refresh token；
- 平台凭据的加密存储、轮换、失效检测；
- 平台素材上传和平台素材 ID 缓存；
- 把统一内容映射为平台标题、正文、话题、封面、分类、原创声明等字段；
- 发布、审核状态查询、删除或撤回（平台支持时）；
- 从官方 API 拉取作品级和账号级指标。

适配器可以按平台拆成独立进程或独立部署单元。控制面只通过版本化 HTTP 协议访问。

## 3. 内容与素材

统一内容分三类：

| `contentType` | 必填内容 | 典型用途 |
| --- | --- | --- |
| `article` | 标题、正文、可选封面/配图 | 书评、书籍解读、工具教程 |
| `image_text` | 标题/文案、1 个或多个图片素材 | 小红书式笔记、抖音图文、微博配图 |
| `video` | 视频素材、标题/文案、可选封面 | 短视频、书籍推荐、口播 |

正文和平台文案在上层以通用结构保存；不同平台的长度、标签、分类、外链和图片数量限制
由适配器声明并在发布前校验。

## 4. 一键发布链

```text
用户选择 1 个内容版本 + N 个平台账号
                  │
                  ▼
          amei 创建发布批次
                  │
       ┌──────────┼──────────┬──────────┐
       ▼          ▼          ▼          ▼
    抖音任务    快手任务    B 站任务    微博任务
       │          │          │          │
       ▼          ▼          ▼          ▼
   平台素材     平台素材   平台素材    平台素材
       │          │          │          │
       ▼          ▼          ▼          ▼
   创建内容     创建内容   创建内容    创建内容
       │          │          │          │
       └──────────┴──────────┴──────────┘
                  │
            审核/发布状态
                  │
            平台作品 ID/URL
                  │
             数据定时回流
```

“一键”只表示用户一次提交，不表示所有平台一定成功。平台审核、OAuth 失效、素材不合规和
限流都可能产生单平台失败；批次必须能表达 `partial` 和 `needs_action`。

## 5. 平台账号与登录

### 5.1 amei 手机号登录

```text
用户手机号 -> amei 发送 OTP -> 校验 -> 自动建号/登录 -> amei JWT
```

这是控制面账号，不等于抖音、B 站等平台的账号。

### 5.2 平台开放平台账号绑定

```text
amei 用户 -> 点击绑定平台
           -> 适配器生成 OAuth 授权 URL
           -> 用户在平台完成授权
           -> 平台回调适配器
           -> 适配器加密保存 token
           -> 返回 accountRef + 脱敏展示信息给 amei
```

平台账号一般通过 OAuth 或平台授权页完成，不以“服务端用手机号密码登录”为默认方案。
各平台手机号注册/登录的真实流程见 `platforms/` 下的逐平台文档。

## 6. 开源复用策略

复用顺序：

1. 官方 SDK：直接作为依赖或封装，优先于自研协议实现。
2. 有明确许可证、最近仍在维护、覆盖目标能力的社区 SDK：可复用协议结构和签名逻辑。
3. 许可证不明、禁止商用、只覆盖网页/逆向协议的仓库：不得作为生产依赖。
4. 仓库存在不代表当前平台权限可用，必须用开发者应用和测试账号实测。

首轮明确结论：

- 抖音官方 SDK `bytedance/douyin-openapi-sdk-go`：Apache-2.0，固定 `a50593c5ccdc31ab5b7cb2153947dfad612bbed9`，可直接依赖复用；
- B 站官方 demo `bilibili-openplatform/demo`：已归档、无 License，只用于核对 token、上传、封面和投稿链，不复制代码；
- 快手 `bububa/kwai-openapi`：Apache-2.0，但最后提交为 2021-04-14，仅参考，不作为当前官方事实；
- 微博 `axiaoxin-com/weibo`：MIT，可参考 OAuth 和 `statuses/share`，不覆盖机构视频；
- `biliup/biliup`：README 明确禁止商业用途并使用网页协议，不进入生产依赖；
- 小红书、视频号：未找到可信、许可清晰、基于官方内容发布 API 的实现，不引入逆向项目。

完整仓库、License、commit 和复用级别见 `13-open-source-reuse.md`。

## 7. 失败与重试

- 适配器 5xx/网络错误：指数退避重试；
- OAuth token 失效：标记账号 `expired`，要求重新授权；
- 平台限流：按 `retryAfter` 延后，不换号绕过；
- 内容审核拒绝：任务失败，保存脱敏原因，不自动改稿重发；
- 素材校验失败：回到内容编辑或媒体转码，不重试平台发布；
- 超时且可能已发布：先按幂等键/平台作品 ID 查询，禁止直接再发；
- 单平台失败不影响批次中的其他任务。

## 8. 部署拓扑

| 组件 | 建议入口 | 网络策略 |
| --- | --- | --- |
| `amei-api` | 公网 HTTPS / 管理内网 | 只暴露用户 API 和后台静态资源 |
| `amei-worker` | 无公网端口 | 调度、重试、指标拉取 |
| `amei-media` | 内网 + 签名上传/下载 | 对象存储私网或公网签名端点 |
| `amei-adapters` | 仅内网 | 按平台独立服务、独立密钥、独立扩容 |
| MySQL | 仅内网 | 控制面与非敏感索引 |
| Redis | 仅内网 | 限流、锁、短任务队列 |
| 对象存储 | 私有桶 | 上传/下载均签名，禁止公开列举 |

OAuth 回调域名建议由适配器或统一回调网关承接，回调后只把 `accountRef` 和脱敏资料交给控制面。

## 9. 关键决策

1. **只走开放平台 API**：不做创作者网页后台、Cookie、抓包或逆向发布；无 API 的平台只做禁用占位。
2. **凭据放适配器**：控制面数据库泄漏不直接导致平台账号被盗。
3. **媒体独立成仓**：视频转码和平台上传解耦，控制面不传大文件。
4. **单平台任务化**：批量发布可部分成功，重试不影响其他平台。
5. **平台能力显式声明**：不支持的视频/图文能力在提交前禁用，而不是发布时才报错。
6. **开源复用需过许可证与事实核验**：社区仓库不能替代官方文档。

## 10. 本期不做

- 平台账号批量注册、养号、换号；
- 验证码识别、风控绕过、非授权抓包或逆向；
- 自动洗稿、批量伪原创和刷量；
- 评论区、私信、点赞等互动自动化；
- 在未取得开放平台权限前承诺六个平台全部自动发布；
- 以搜索引擎收录作为产品承诺。
